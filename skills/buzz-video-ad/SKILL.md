# SNS広告動画（buzz-video-ad）

スマホ素材＋ロゴ → 構成表（project.json）→ テンプレートで描画 → BGM・効果音・ナレーションを付けて納品、までを一式で行う。
編集エンジンとテンプレートは `scripts/` に揃っている。毎回コードを書き直さず、**構成表を書いて静止画で確認しながら詰める**のが基本。

```
S="${CLAUDE_SKILL_DIR}/scripts"   # このスキルの scripts フォルダ（展開されていなければ、この SKILL.md の隣の scripts）
PY=$(bash "$S/env.sh")          # 専用のPython環境（初回は自動作成）。--check で ffmpeg / 音声エンジン等も確認
```
- 初めて使うマシンでは、先に `bash "$S/setup.sh"` を実行する（ffmpeg・Python環境・HDR変換表・フォントの確認。足りないものは Homebrew で入れる。`--check` なら確認だけ）。
- Windows でも同じ手順で動く（Claude Code が Git Bash で実行する。Git for Windows が必要）。`"$PY"` は UTF-8 で動く起動用スクリプトなので、そのまま使う。書き出しは Mac より遅い。

## 進め方

### 1. 素材を受け取って中身を見る
- 素材フォルダとロゴ画像の場所を確認する（チャットに貼られたロゴ画像は、ファイルとして保存してから使う）。
- 作業フォルダを決め（例：`<案件名>_広告動画/`）、`"$PY" "$S/probe.py" <素材フォルダ> --out work/footage` を実行する。
  - probe.py はフォルダ内の動画・画像をすべて読む。`~/Downloads` のように関係ないファイルが多い場所なら、作業フォルダに `footage/` を作り、使う素材だけをシンボリックリンク（`ln -s`）で入れてから渡す。
  - レーザー・光脱毛などの施術機器、カメラのフラッシュ、点滅する照明が映る素材なら必ず `--flash` を付ける。1コマだけの閃光を全コマから探す（全コマを読むので、PCが空いていれば数秒〜数十秒、混んでいると数分かかる）。見つかったクリップには `"flash_guard": true` を付ける。
- `overview.jpg`（全クリップ一覧）と各クリップのコンタクトシートを**実際に見て**、次のことを書き出す。
  - 使えるカット
  - 上下逆さのクリップ（→ `"rot": 180`）
  - 60fpsのクリップ（スローモーションに使えるのはこれだけ）
  - HDRのクリップ（→ `prep_hdr.py` をこのマシンで一度だけ実行。`~/.local/share/sns-ad-video/hlg2sdr_65.cube` があれば済んでいる）
  - 映ってはいけないもの：他社ロゴ、販促POP、PC画面、個人情報、一般客の顔、機器メーカーのロゴ・機種名・操作画面
- 業種を判断する。鍼灸・整骨・クリニック・化粧品・健康食品は広告規制が強いので、[references/ad-rules.md](references/ad-rules.md) を先に読む。

### 2. 選択式で質問する（ここは省略しない）
ユーザーは選択式で答えるのを好む。AskUserQuestion を使い、**1回目は4問**（テイスト・比率・長さ・最後の導線）、**2回目は該当するものだけ**（BGMの雰囲気、口コミ風の形式、ナレーションの声）を聞く。
質問文と選択肢の正確な文面と「おすすめ」の付け方は [references/questions.md](references/questions.md) にある。素材を見たうえで、合う選択肢を先頭に置いて「（おすすめ）」と付ける。

### 3. ロゴを準備する
`"$PY" "$S/logo_prep.py" brand/logo.png` を実行し、出力された `logo_preview.png`（上：明るい背景用、下：暗い背景用）を見る。
- ロゴの形・色は変えない。暗い背景用で変えるのは「黒っぽい無彩色の部分を白にする」ことだけで、元のロゴが暗い背景でも読めるなら何も変えない。
- プレビューの色がおかしい（ロゴの一部が黒く・白くなった、イラストに筋が出た）ときは、出力ファイルを手で差し替えず、次のどれかを付けて作り直す。
  - `--ink dark`：明るい背景向けに作られたロゴ
  - `--ink light`：白抜きのロゴ（暗い背景向け）
  - `--ink keep`：色を一切変えない（背景ごとデザインされたバッジ型のロゴで `--keep-bg` を付けたときは、これが既定）
- `NOTE: pale logo` と出たら淡い色のロゴ。明るい画面の上では読めないので、エンドカードを暗くし、冒頭のロゴは素材の暗い部分に重ねる（[references/tastes.md](references/tastes.md)「淡い色のロゴ」）。暗い背景でまだらに見えるロゴは、クライアントに白抜き版のデータがないか聞く。
- `accent` が空ならロゴにブランド色がない。看板・公式サイト・内装から1色決める（決められなければ既定の金色のまま）。`accent_muted: true` は、グレージュなど落ち着いた色をロゴから取ったという意味で、そのまま使ってよい。

### 4. 構成表を書く
`project.json` を作る。
- 書式は [references/spec.md](references/spec.md)、テイストごとの項目と例は [references/tastes.md](references/tastes.md) にある。完全な例は [examples/salon/project.json](examples/salon/project.json)。
- 選んだテイストごとに `versions` を1つずつ作る。比率は書き出し時に指定するので、同じ構成のまま全比率に使える。
  ただし縦の素材から16:9を作るときは、ショットごとに `"aspect": {"16:9": {...}}` で切り取り方を決める（[references/layout.md](references/layout.md)「縦の素材から16:9」）。
- ぼかし位置や画面の中心を決めるときは、`"$PY" "$S/grid.py" <クリップ> <秒> [--rot 180]` で座標入りの画像を作って読み取る。
- 文言の決め方：
  - 冒頭1秒で「何の店か」が分かるようにする。
  - テロップは1行15字前後まで。
  - 効果を言い切る表現・No.1・ビフォーアフターは使わない。

### 5. （Vlogのとき）ナレーションを作る
`"$PY" "$S/tts.py" project.json --version <名前>` を実行する。
- Whisperで聞き取り確認を自動で行う。点数が低い行は、表示された聞き取り結果を見て対処する。
  - 読み間違い → `speech` をかなで書き直す。
  - 店名が漢字で聞き取られているだけ → `voice.aliases` に登録する。
- 直した行だけ作り直すときは `--line 3 9` を付ける。

### 6. 静止画で確認しながら詰める
```
"$PY" "$S/render.py" project.json --version <名前> --aspect 9:16 --sheet 0.5 --guides     # 0.5秒ごとの一覧
"$PY" "$S/render.py" project.json --version <名前> --aspect 9:16 --stills 1.0 5.2 --guides  # 気になる瞬間
```
- 選んだ**すべての比率**で、テロップの出る瞬間を必ず見る。比率を変えると切り取られる範囲が変わり、ぼかし対象が新しく見えたり、顔にテロップがかかったりする。
- 直し方：shot の `"aspect": {"1:1": {...}}` で、その比率だけ中心やズームを変える。
- 見るポイント：
  - 黄色の枠（セーフゾーン）の中に収まっているか
  - 顔にテロップがかかっていないか
  - ぼかしの位置が合っているか
  - 白いテロップや淡い色のロゴが、明るい壁・窓の上で読めるか（読めなければ暗い面に置くか、テロップの `theme` を変える）
  - エンドカードの導線が2秒以上出ているか
- `flash_guard` を付けたショットは、静止画でも動画と同じように閃光が消える。

### 7. 書き出し → 仕上げ
```
"$PY" "$S/render.py" project.json --version <名前> --aspect 4:5 --video         # 並列で書き出し（無音のマスター）
"$PY" "$S/finish.py" project.json --version <名前> --aspect 4:5                 # BGM作曲・ミックス・-14 LUFS・軽量版・カバー・QA
```
- `finish.py` は次の作業をまとめて行う。
  - BGM：バージョンごとに一度作曲し、全比率で使い回す。
  - 効果音・ナレーションのミックス
  - 音量調整
  - 書き出し
  - 30MB未満の軽量版とカバー画像の作成
  - 技術チェック（`report_<比率>.json`）
- 最初の1本ができたら、軽量版を送り（SendUserFile があればそれで。なければファイルの場所を伝える）、残りの見込み時間を一言添える（長い作業中に黙らない）。

### 8. 仕上げのチェック
- 技術面は `report_*.json` で次を確認する。
  - 音量が -14±1 LUFS か
  - True Peak が -1 dBTP 以下か
  - 撮影部分にコマの重複が続いていないか（`dup_seconds`）
- 別のエージェント（Agentツール）に静止画と構成表を渡し、広告規制・見え方・誤字をチェックさせる。依頼文の型は [references/qa.md](references/qa.md)。
- 指摘を直したら、該当する比率だけ書き出し直す。

### 9. 納品
- `納品/`（project.json の `out_dir`）に、次のものを揃える。
  - 動画
  - 軽量版
  - カバー画像
  - `投稿文案.txt`
  - `メモ.txt`（構成・各テイストの狙い・配信前の確認事項）
- 型は [references/delivery.md](references/delivery.md) にある。ギガファイル便やGoogleドライブへのアップロードは、頼まれたときだけ行う。
- 報告は短く書く。何を作ったか、どこにあるか、配信前にユーザーが確認すべきこと（規制・音声のクレジット）を伝える。

## 判断の目安
- **テイストの向き不向き**
  - スタンダード：認知・指名に向き、迷ったらこれ。
  - モーション：TikTokやストーリーズで最初の1秒で止めたいとき。
  - シネマティック：雰囲気・高級感・ブランドを見せたいとき。
  - Vlog：広告っぽさを抑えたいとき。
  - LINE風：口コミ感を出したいとき。ただし医療・鍼灸では体験談にあたるので避けるか、公式アカウントのQ&A形式にする。
- **比率**
  - 縦の素材から16:9を作ると、何も指定しなければ「中央に素材＋左右ぼかし」になる（render.py が警告を出す）。広告としては弱いので、ショットごとに `"aspect": {"16:9": {"fit": "cover", "center": [...]}}` で横長に切り取る。4K素材なら十分きれいで、1080pの素材でも内装なら見られる（少し甘くなる）。
  - 縦長の画面で考えた中心位置が、比率を変えても合っているか必ず確認する。
- **テンポ**
  - 速めの版が好まれやすい（実際の案件では、約2割短縮した版が採用された）。迷ったら少し速めに作る。
  - カットは2〜3秒、テロップは1.2秒以上表示する。
- **BGM**
  - 毎回オリジナルを作曲する（著作権の心配がない）。市販の曲や店内BGMの音は使わない。

## つまずきやすい点（詳細は各 reference）
- **スロー**：0.5倍スローは60fpsのクリップだけで使える。30fpsで使うとカクつく（spec が警告を出す）。
- **iPhoneのHDR素材**：白っぽく眠い色になる。`prep_hdr.py` をマシンで一度実行すれば、以降は自動で変換される。
- **レーザー・フラッシュの閃光**：1コマだけ光るので、コンタクトシートでは見落としやすい。`probe.py --flash` で見つけ、`flash_guard` で消す。
- **淡い色のロゴ**：明るいカードや明るい壁の上では読めない。暗いエンドカードと、素材の暗い部分を使う。
- **カットの頭の余白**：ディゾルブなどの場面転換は、カットの `in` より少し前（0.1〜0.2秒）から素材を使う。`in` が0に近いと「needs source -0.06…」というエラーになるので、`in` を少し後ろにずらす。
- **タイミングの計算**：素材のコマ番号は必ず floor で計算する（round だとコマが重複・欠落する）。エンジンは対応済み。
- **ロゴのきらめき**：強すぎると金色などの色が白く飛ぶ。ロゴの色を変えたい場合は、必ずクライアントの承認を取る。
- **ナレーションとBGM**：ナレーション中のBGMは、RMSで声を検出して400msの保持をかけたうえで下げる。単純な方法だと下げ足りなかったり、音量がうねったりする。
- **AACの音割れ**：AACに変換するとピークが上がる。finish.py が True Peak を測って自動で抑える。
- **ファイルサイズ**：フィルムの粒子は容量を大きくする。シネマティックは finish.py が `-tune grain` で再エンコードする。
- **LINE風トーク**：作り物っぽい画面は安っぽく見える。ステータスバー・かなキーボードの配列・時刻の順序まで自然にそろえる（tastes.md）。「※画面はイメージです」の表示は消さず、LINE のロゴや名前は使わない。
